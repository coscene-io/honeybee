# Moment DOM 性能优化：实现与验收记录

日期：2026-09-19。实现分支：`codex/moment-timeline-performance`；生产代码：`96d16c1bc`。

**结论：实现及相关功能测试已交付，性能验收尚未全部通过。** 保留逐条 DOM 展示、原生手柄和完整数据，未加入 Canvas、密度图、抽样或后端变更。1,000 条的各操作反馈代理指标达到 50 ms 内；5,000 条的缩放、部分重叠/连续场景仍超标。21,600 条短片段达到本轮 150 ms / 500 ms 阻塞代理指标，普通重叠、同轨连续片段仍存在压力边界。不能据此宣称所有场景稳定 60 FPS。

## 已实现

- 命中集合相同且事件对象未变时不写 store；同 ID 内容更新仍会刷新。每条 EventTick/列表卡片仅订阅自身状态，静态条形层和 tooltip 详情与高频位置更新分离。
- 共享支持长区间重叠的时间索引、按 ID/轨道查询和布局缓存；字幕复用全记录布局，仅更新变化的激活集合。缓存使用 WeakMap，每份数据最多保留两个 viewport 布局。
- 坐标压缩、区间最小值查询替代逐轨扫描，保留排序、容差、最小轨道优先和裁剪规则。两种吸附各自保留原有等距规则，拖拽期间复用不变邻居的边界排序。
- 底部时间轴按可见轨道加上下两条预渲染；保留完整高度、轨道编号与居中关系。拖拽、联动编辑、焦点和操作菜单关联条目固定挂载。
- 片段拖拽、联动编辑、播放指针 seek 按帧合并；松手同步处理最后位置，取消/卸载清理。滚轮累计输入后每帧应用，保持实时完整排轨和既有提交/回滚流程。
- EventsList 单次线性分组，预先格式化/搜索，动态高度虚拟列表；MomentsBar 固定宽度虚拟列表。按 ID 自动定位、滚动锚点、活动行状态和身份去重查询得到保留。
- 浏览器采样额外定位到 `box-sizing: inherit` 在密集移动节点上的高额样式重算，以及每个 EventTick 重复执行 Emotion 样式序列化。轨道内容显式沿用 `border-box`，共享状态类名组合，保留条形结构和计算尺寸。

## 测量口径与局限

- Apple M4 Pro，同一机器；Playwright Chromium 148.0.7778.96，1440 × 900，生产构建，实际项目字体、CssBaseline 和组件/provider。API 和播放器使用 mock；不包括网络、解码或图片 URL 获取成本。
- 优化前为 `e6980d208`（仅增加合成 fixture/参考测试，生产逻辑等同 `551310262`），主矩阵优化后为 `96d16c1bc`。前后相同 fixture 和交互脚本。测试过程中不并行运行构建或其他浏览器基准。
- 一小时数据：`short` 为 0.1 秒短片段；`continuous` 为首尾相接片段；`overlapping` 为 5 秒重叠片段；`long` 为从各自开始延伸至记录终点。
- “反馈 P95”是浏览器捕获输入到两次 requestAnimationFrame 的代理值，**不是硬件呈现时间或 INP**。hover 70 次、拖拽约 42 次输入；缩放仅 3 次，所谓 P95 实际接近最大值，不能视作充分统计。拖拽按条形中心点击，极窄条形会落入原生边缘手柄；该项并非独立覆盖所有编辑方式。
- 播放阶段包含启动、停止和缩放后跟随当前时间的视口跳转，不能把它直接解读为纯稳态字幕更新耗时。首次挂载单列，不混入操作指标。
- 本机 rAF 空闲间隔约 8.3 ms（约 120 Hz），**未固定为计划要求的 60 Hz 环境**。JSON 中 `fps` 为 rAF 平均频率，并非逐帧实际呈现测量；连续片段开启关联视图时存在低于 60 的结果。正式 60 Hz 验收仍需补测。

## 弱 CPU、长片段和清理检查

4 倍 CPU 降速（模拟补充，不是真实低端设备），1,000 条短片段、全部关联视图开启：悬停 57.6 ms、缩放 125.6 ms、拖拽 146.1 ms、列表滚动 67.9 ms，未达到常规 50 ms 目标。原始值见 `results/moments-2026-09-19/cpu4.json`。

长片段压力测试使用 5 次横跨时间轴的 hover、每个组合最多 30 秒。21,600 条时只挂载 10 个可见条形，证明纵向虚拟化生效；同时命中上万条 moment 的详情格式化、tooltip 与字幕输出仍无法省略：开启关联视图的 hover 代理值约 1,989 ms，最长 hover 任务约 1,974 ms。该类场景没有通过流畅度目标。1,000/5,000/21,600 条开启字幕的播放阶段均因大量字幕覆盖测试按钮而失败；21,600 条关闭关联视图也在拖动阶段触及总超时，不能将这些组合认定为完整功能通过。超时后能够关闭页面并继续下一组合，数据内恢复/真实工作区的恢复路径尚未完成验证。原始异常保存在 `long.json`。CPU/长片段补充采样基于 `40c9988ec`，早于最后的字幕缓存和底部留白修复，未将其作为最终提交的完整验收。

浏览器视觉/功能检查基于最终生产代码：

- 12 条连续片段，前后全部条形及子手柄的矩形、padding、边框、背景、box-sizing 和透明度相同；已实际查看截图。并非全界面逐像素回归，也未覆盖所有主题/分辨率。
- 搜索 `Moment 9` 仅显示一条；分组折叠/展开成功；右键命中同一 moment 后均提供 `Edit Moment` / `Loop Play`，无页面异常。截图与原始几何保存在 `visual-before` / `visual-after`。
- 12 轮替换 5,000 级与 1,000 条前端数据、缩放及滚动，主动 GC 后 Documents 一直为 1、JSEventListeners 一直为 374；JS 堆约 27–41 MB 波动，末次约 32 MB，未出现单调持续增长。这是有限时长的合成数据清理检查，不证明不存在所有泄漏，也未覆盖真实 record/API 切换与网络图片加载。
- benchmark 中 MomentsBar 接收固定 fixture；该页面不覆盖保存后该卡片列表的数据重算。提交/回滚与时间精度由相关单测补充，完整编辑联动仍需真实工作区复验。

## 复测

安装项目原有依赖后，在仓库根目录执行，两个服务器应分开启动；性能测试串行执行。

```sh
node node_modules/@rspack/cli/bin/rspack.js build --mode production --config benchmark/moments.rspack.config.ts
python3 -m http.server 8765 --bind 127.0.0.1 --directory benchmark/.webpack-moments
```

另一终端：

```sh
MOMENT_DISTRIBUTIONS=short,continuous,overlapping node benchmark/moments-perf.mjs http://localhost:8765 after.json
MOMENT_COUNTS=1000 MOMENT_DISTRIBUTIONS=short node benchmark/moments-perf.mjs http://localhost:8765 cpu4.json 4
MOMENT_COUNTS=1000,5000,21600 MOMENT_DISTRIBUTIONS=long MOMENT_STEPS=5 MOMENT_TIMEOUT_MS=30000 node benchmark/moments-perf.mjs http://localhost:8765 long.json
node benchmark/moments-smoke.mjs http://localhost:8765 smoke-output --soak
```

前后对比：在 `e6980d208` 独立 checkout 中复制本提交的 benchmark 配置、入口和脚本，用旧生产源码构建，另开 8766 端口，再以相同环境变量运行 `moments-perf.mjs`。勿并行跑两端测试。正式验收应增加缩放样本、固定 60 Hz、测量真实呈现延迟，并在目标设备/真实记录中复测。

后续若继续优化，优先检查大量同轨 DOM/联动手柄在 viewport 变化时的 React 更新、布局和列表自动定位开销；继续维持完整数据和原生命中规则。本轮不会自行切换 Canvas 或密度图方案。
