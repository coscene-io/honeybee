# Bombus → Honeybee 时间轴迁移核对

2026-10-20。核对基准：Bombus `origin/main` 的 `930fd531792121e36814f2ab4bb0dda1830b20c6`，以及 #260 的按钮居中和表头文案修复 `e0a9d66cc55f3a9cd350fb91c2cccf77851252b1`；Honeybee 修复前为 `51d523ca2b3913672d4515330a9255d970d9be91`。

此前迁移并不完整：Moment 右键菜单只保留了编辑和循环播放，遗漏了 Bombus #252 的查看、聚焦、游标对齐和确认删除。以下清单针对可共用的桌面时间轴交互，不代表两个产品的任务模型相同。

| 确认删除 | 本轮补齐；独立检查删除权限及归档状态，确认后再次检查权限与条目是否仍存在，复用 Honeybee 的附件清理路径 |
| 循环播放 | 保留 Honeybee 原有菜单入口，零时长禁用 |

侧栏的聚焦请求通过共享时间轴状态交给 Scrubber 消费；请求只匹配当前可见集合中的条目，避免切换记录后聚焦旧数据。侧栏编辑同样保留完整的原始元数据；`_doubtful` 只从展示列表隐藏，避免无关编辑意外清除存疑状态。

菜单弹层隔离指针事件，避免触发底层时间轴交互。菜单和详情解析最新条目，条目被移除/过滤时关闭；候选列表同样剔除隐藏或已移除的条目。时间更新仅写 `trigger_time`、`duration_nanos`、`duration`，保持 Honeybee 新旧时长字段兼容；同一条目的时间更新防止重复提交。失败时只回滚仍属于当前乐观更新的状态，同步恢复仍未被用户修改的编辑器时间标记，并刷新权威数据，避免旧请求覆盖新记录。

## 产品边界

以下 Bombus 能力依赖 Starbase 的任务/文件模型和 RPC，未直接复制到 Honeybee：

- 标注/质检双轨、Moment 类型及任务执行人的写权限规则。
- SOP/原子技能绑定、语义分组与相应的任务轨道操作。
- 文件有效范围的左右裁剪和任务结果写入。

Honeybee 继续使用自身项目/记录归档状态、Event 更新和删除权限、最多五级项目自定义字段分组。没有添加 Starbase 依赖或伪造对应后端能力。

## 验证

- 回归涵盖：直接右键及菜单指针事件不 seek、轨道/重叠子轨命中、只读详情和 Escape 关闭、聚焦/复位、侧栏共享聚焦请求及只读查看、最新游标和最新条目、纳秒精度及字段掩码、越界/非正时长、删除取消/确认/附件清理、确认期间权限撤回、重复时间写入、失败回滚、打开的编辑器标记同步，以及切换记录后的迟到失败。
- Codex 内置浏览器的 localhost 真实 Dev 记录确认菜单六个入口可见；右键和聚焦前后播放时间保持一致，聚焦改变缩放，复位恢复全记录视野。侧栏的 5 个聚焦入口也已出现，侧栏聚焦与菜单聚焦得到相同视野且播放时间不变。未在真实记录上执行时间修改或删除；写操作与失败分支使用测试 API 验证。
- 合成桌面 fixture 用完整鼠标右键序列确认：游标保持原时间；无效的终点对齐禁用；打开并取消删除后 8 条 Moment 全部保留。条形主体、左右缩放柄的右键不会进入拖动分支或清除编辑器标记，联动边界的右键定位到后一个 Moment。
- 类型检查、全仓 lint、Web 生产构建和独立时间轴生产构建通过（构建分别保留 2/3 个体积建议）。全量单进程测试曾在本机 Node 24.12.0 的 V8 GC 中以 `SIGSEGV` 退出，崩溃帧位于 `ClearStaleLeftTrimmedPointerVisitor`；后续在分片运行中也复现了该原生崩溃；最终使用本机已有、同样满足项目 24.x 约束的 Node 24.19.0，Jest 单 worker 并设置 1024MB 空闲内存回收上限。未修改项目依赖或产品实现来规避崩溃。
- 最终全仓覆盖 346 个套件：345 个通过、1 个原有跳过项；共 3,574 项测试和 38 个快照通过。完整 worker 运行中 `BagView.test.tsx` 与 `link-target.test.ts` 遇到原生 `SIGSEGV`，分别在独立进程中重跑后 4/2 项测试通过；已按文件集合核对，覆盖与完整发现列表一致。这不代表完整单进程运行没有崩溃。
- 本次只验证桌面。生产基准构建的 bundle 大小建议不作为帧率或真实解码验收。
